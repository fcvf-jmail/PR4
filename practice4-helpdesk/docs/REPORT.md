## 1. Система и стратегия
HelpDesk: браузер (public/app.js) → HTTP API (src/app.js) → логика и хранилище (src/core.js, src/store.js).
- **Unit (Jest)** — чистые функции `core.js`: валидация, нормализация, переходы, фильтр/сортировка (быстро, много граничных значений).
- **Integration (Jest + fetch)** — реальный HTTP-сервер на порту 0: коды 200/201/400/404/409, тело JSON, состояние после операций.
- **E2E (Cypress + Page Object)** — только пользовательские сценарии и то, что видно лишь в браузере (экранирование HTML).
- Неэффективно в браузере: граничные длины 4/5/80/81 (U-04) и матрица переходов статусов (U-07) — десятки комбинаций, в UI они тянут за собой лишние клики и нестабильность.

## 4. Карточки дефектов
**Д-1 (данные). Нормализация темы не схлопывает пробелы и длина считается до нормализации.**
Требование «Тема»; тесты U-01/02, U-04, I-01, I-04. Вход `"ab    c"`, `"   abcd   "`, `"Сбой   VPN"`. Ожидалось: тема `Сбой VPN`; `"   abcd   "` → 400. Получено: пробелы остались внутри; `"   abcd   "` принимается (длина 10 > 5). Причина: `normalizeTitle` делал только `trim()`, а `validateTicketInput` проверял `input.title.length`. Исправление: `.replace(/\s+/g,' ')` и валидация по нормализованной теме. RED: `docs/logs/01-red.log`; GREEN: `02-green-defects.log`.

**Д-2 (логика/API). Разрешён переход new → resolved.** Требование «Переходы состояний»; U-07, I-11. `PATCH /api/tickets/1/status {"status":"resolved"}` для new. Ожидалось 409, получено 200. Причина: условие `to === 'in_progress' || to === 'resolved'` в `canChangeStatus`. Исправлено: оставлено только `in_progress`. Повторный прогон — зелёный.

**Д-3 (поиск). Поиск чувствителен к регистру.** U-08/09/10, I-06. `search=vpn` не находит «VPN недоступен». Причина: `includes` без `toLowerCase`. Исправлено: приведение к нижнему регистру обеих сторон.

**Д-4 (сортировка). Порядок приоритетов обратный.** U-11, I-07, E-05. Ожидалось high→medium→low, получено low первым. Причина: `RANK[a]-RANK[b]` вместо `RANK[b]-RANK[a]`.

**Д-5 (интерфейс, безопасность). XSS: HTML из ввода интерпретируется.** E-07. Ввод `<b>Жирная</b> тема` и `<img src=x onerror=…>`. Ожидалось: текст; получено: разметка отрисована и обработчик выполнился. Причина: подстановка `ticket.title/description` в `innerHTML` без экранирования. Исправлено: `escapeHtml()` в `public/app.js`. RED: `06-cypress-xss-red.log`; GREEN: `05-cypress-green.log`.

**Д-6 (дефект теста, найден при повторных прогонах).** I-07 нестабильно падал: заявки создавались в одну миллисекунду, `createdAt` совпадал. Исправлено паузой 5 мс в подготовке данных. Вывод: нестабильный красный тест сначала проверяют на дефект самого теста.
