# BDD-сценарии (Given / When / Then)

## Сценарий 1 (успешный): принятие корректной заявки
```gherkin
Сценарий: принятие корректной заявки
  Дано открыт экран HelpDesk с четырьмя заявками
  Когда пользователь вводит тему "  Сбой   VPN в корпусе  ",
        описание "Не удается подключиться к учебной сети", категорию "Сеть", приоритет "Высокий"
  И нажимает «Создать заявку»
  Тогда в форме отображается "Заявка №5 создана"
  И счётчик реестра показывает 5
  И в списке есть заявка с темой "Сбой VPN в корпусе" (пробелы нормализованы)
```
Автотесты:
- E2E: `cypress/e2e/tickets.cy.js` → **E-01** «создаёт заявку через форму и показывает её в списке»
- API: `tests/integration/api.test.js` → **I-01** «созданная заявка видна в GET с теми же данными»

## Сценарий 2 (негативный): отклонение слишком короткой темы
```gherkin
Сценарий: отклонение заявки с короткой темой
  Дано открыт экран HelpDesk с четырьмя заявками
  Когда пользователь вводит тему "abcd" и описание "Достаточно длинное описание"
  И нажимает «Создать заявку»
  Тогда отображается "Тема должна содержать от 5 до 80 символов"
  И счётчик реестра остаётся 4
```
Автотесты: **E-02** (Cypress), **I-03/I-04** (HTTP 400, количество заявок не меняется), **U-04** (границы).

## Сценарий 3 (запрет перехода статуса)
```gherkin
Сценарий: пропуск этапа запрещён
  Дано существует заявка №1 со статусом new
  Когда клиент отправляет PATCH /api/tickets/1/status {"status":"resolved"}
  Тогда сервер отвечает 409
  И статус заявки в GET /api/tickets остаётся new
```
Автотесты: **I-11** (API), **U-07** (`canChangeStatus('new','resolved') === false`).
